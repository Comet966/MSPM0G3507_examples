# 硬件迁移指南

## 迁移边界总览

```
ApplicationLayer/   ← 100% 可移植，零硬件依赖
Algorithm/          ← 100% 可移植（纯数学）
FunctionalModule/   ← 大部分可移植，GraySensor.c 需小改
HardwareDriver/     ← 全部需要重写（MCU专属）
ti_msp_dl_config.*  ← 删除，替换为目标平台初始化
```

迁移工作量集中在 **HardwareDriver** 层的 6 个模块，以及 **GraySensor.c** 中内嵌的 ADC 调用。

---

## 一、需要完全重写的模块

### 1. `System.c / System.h` — 系统时钟与延时

**当前实现**：直接读 `SysTick->VAL` 和 `SysTick->LOAD` 寄存器，假设系统时钟 80 MHz。

**必须实现的接口**：

```c
// 毫秒计数（从上电开始累加，必须由定时中断驱动）
uint32_t millis(void);

// 微秒计数（精度要求 ≤ 5 μs）
uint32_t micros(void);

// 阻塞延时
void delay_ms(uint32_t ms);
void delay_us(uint32_t us);

// 以下是别名，直接调用上面两个即可
void Delay_Ms(uint32_t time);
void Delay_Us(uint32_t time);
void delay(uint32_t ms);
void delayMicroseconds(uint32_t us);
```

**移植注意**：
- `millis()` 由 SysTick 1 ms 中断递增 `sysTickUptime` 实现，对应 `user/main.c` 中的 `SysTick_Handler()`（当前为空，需要填充 `sysTickUptime++`）
- STM32 可直接使用 HAL_GetTick() / HAL_Delay()，但需提供 `micros()` 的 TIM 实现
- `delay_us` 在 IIC 和 BMI088 驱动中被调用，精度影响通信稳定性

---

### 2. `Timer.c / Timer.h` — 定时中断调度

**当前实现**：4 个硬件定时器，各自触发 ISR 调用外部 `duty_Xhz()` 函数。

**必须实现的接口**：

```c
// 初始化并启动全部定时器，使能 NVIC
void TimerInit(void);
```

**ISR 调度要求**（这些函数在 `main.c` 中定义，TimerInit 负责定期调用它们）：

| 函数 | 频率 | 最大执行时间估算 |
|------|------|----------------|
| `duty_200hz()` | 200 Hz（5 ms） | ~2 ms（含 ADC 8路轮询） |
| `duty_100hz()` | 100 Hz（10 ms） | <0.1 ms |
| `duty_10hz()`  | 10 Hz（100 ms） | <0.1 ms |
| `duty_1000hz()` | 1000 Hz（1 ms）| 空函数，可不实现 |

**移植注意**：
- `duty_200hz` 耗时最长（含 8 次 ADC 采样），5 ms 周期内必须能完成
- STM32 用 TIM6/TIM7（基本定时器）触发，优先级建议：200 Hz = 5，100 Hz = 6，10 Hz = 7
- 编码器中断优先级（当前为 1）必须高于 200 Hz 定时器，否则高速转动时计数丢失

---

### 3. `Pwm.c / Pwm.h` — 4路电机 PWM

**当前实现**：TIMA0 定时器，计数周期 1000，4路互补 PWM，频率约 10 kHz。

**必须实现的接口**：

```c
// 启动 PWM 定时器（在 MotorInit 中调用）
void PWMStart(void* timer_instance);  // 参数在移植时可改为 void

// 停止 PWM 定时器
void PWMStop(void* timer_instance);

// 设置 4 路 PWM 占空比，范围 0~1000（对应 0%~100%）
// 通道顺序：左前、右前、右后、左后（按原代码 MotorsPWMSet 中的调用顺序）
void PWM_Output(uint16_t width1, uint16_t width2,
                uint16_t width3, uint16_t width4);
```

**原始调用关系**（`MotorsPWMSet` 中）：

```c
// pwm[0]=左前, pwm[1]=左后, pwm[2]=右前, pwm[3]=右后
PWM_Output(pwm[0], pwm[2], pwm[3], pwm[1]);
// 实际 Pwm.c 内部: 通道0=width1, 通道1=width2, 通道2=width3, 通道3=width4
```

**移植注意**：
- 内部实现将输入取反：`实际占空比 = 1000 - width`，这意味着 width=0 时全速，width=1000 时停止——这是**低有效**逻辑，移植时保留该行为，或修改电机驱动器接线
- PWM 频率推荐 8~20 kHz（有刷电机），STM32 用 TIM1 或 TIM8（高级定时器）的 4 路 CCR

---

### 4. `EncoderExti.c / EncoderExti.h` — 编码器计数（外部中断）

**当前实现**：B 相上升沿触发中断，中断内读 A 相电平判断方向，直接写 `Car.Motors->Encoder*.EncoderCount`。

**注意**：这是唯一一个在 HardwareDriver 层直接访问全局 `Car` 对象的文件，存在跨层耦合。

**必须实现的接口**：

```c
// 编码器中断初始化（在 EncodersInit 中调用）
// 使能两路编码器的外部中断
void EncoderExtiInit(void);

// 两个 ISR，内部逻辑固定：
// B相中断触发 → 读A相 → A=高则正转(count++)，A=低则反转(count--)
// 写入目标：Car.Motors->EncoderLeftFront->EncoderCount
//           Car.Motors->EncoderRightFront->EncoderCount
```

**移植注意**：
- STM32 使用 EXTI 线，GPIO 配置为上升沿触发输入
- M0+ 平台（如本项目）中断优先级只有 4 级（0-3），编码器优先级设为 1（最高为 0）
- 当前代码对左后、右后编码器计数器也清零，但 ISR 只更新左前、右前，**左后/右后始终为 0**——移植时保持该行为（联动控制）

---

### 5. `Uart.c / Uart.h` — 串口通信

**当前实现**：UART0（调试，115200）+ UART1（HiPnuc，256000）。

**必须实现的接口**：

```c
// 初始化两路 UART，使能接收中断
void UsartInit(void);

// UART0 阻塞发送单字节（调试输出）
void uart0_send_char(char ch);

// 格式化整数输出（内部调用 uart0_send_char）
void uart_printf(int data);
```

**UART0 接收协议**（在 ISR 中实现）：

```c
// 接收 0xA5 → 触发短按 KeyShortPressProcess(&Car)
// 接收 0xA6 → 触发长按 KeyLongPressProcess(&Car)
// 其他字节 → 原样回显
void UART_0_INST_IRQHandler(void);  // 名称按平台修改
```

**移植注意**：
- `uart_printf` 使用 `sprintf` 将 int 转字符串后逐字节发送，阻塞时间约 `字符数 × 87 μs`（115200 baud），在 200 Hz ISR 中调用有阻塞风险，比赛时应全部注释
- UART1 接收中断当前为空实现（只清标志位），HiPnuc 解析未接入主流程

---

### 6. `IIC.c / IIC.h` — 软件模拟 I²C（仅用于 OLED）

**当前实现**：纯 GPIO 位拆，SCL=PA21，SDA=PA22，延时用 SysTick->VAL 空读。

**必须实现的接口**（宏或函数，供 `Oled.c` 调用）：

```c
// GPIO 操作宏，移植时重定向到目标平台的 GPIO 写函数
#define OLED_W_SCL(x)   // x=1 拉高，x=0 拉低
#define OLED_W_SDA(x)   // 同上

// I²C 时序函数（Oled.c 直接调用）
void MYIIC_Start(void);
void MYIIC_Stop(void);
void MYIIC_Write_Byte(u8 Byte);
void MYIIC_Wait_Ack(void);

// 位时间延时（约 1~5 μs 即可，OLED 不要求精确时序）
void IIC_delay(void);
```

**移植注意**：
- 当前延时靠读 `SysTick->VAL` 4次（约 50 ns × 4 = 200 ns），在低频 MCU 上需改为 `delay_us(1)` 或 NOP 循环
- 若目标平台有硬件 I²C，可直接替换整个 `IIC.c` 实现，但需保持以上函数签名不变（`Oled.c` 会调用）

---

### 7. `BMI088Middleware.c / BMI088Middleware.h` — SPI 中间层（BMI088 IMU）

**当前实现**：SPI1（10 MHz），两路 CS 用 GPIO 软件控制。

**必须实现的接口**：

```c
// 片选控制（拉低 = 选中，拉高 = 释放）
void BMI088_ACCEL_NS_L(void);   // ACC_CS → 低
void BMI088_ACCEL_NS_H(void);   // ACC_CS → 高
void BMI088_GYRO_NS_L(void);    // GYRO_CS → 低
void BMI088_GYRO_NS_H(void);    // GYRO_CS → 高

// SPI 全双工单字节收发（发送 txdata，返回同时收到的字节）
uint8_t BMI088_read_write_byte(uint8_t txdata);

// 延时（BMI088 上电序列需要）
void BMI088_delay_ms(uint16_t ms);
void BMI088_delay_us(uint16_t us);

// 以下两个当前为空实现，移植时也可留空（SysConfig 已初始化外设）
void BMI088_GPIO_init(void);
void BMI088_com_init(void);
```

**移植注意**：
- 当前 `BMI088_read_write_byte` 先发后收，等待 BUSY 两次——这是阻塞轮询，移植到 STM32 可用 `HAL_SPI_TransmitReceive()` 替代
- BMI088 SPI 模式为 Mode 3（CPOL=1，CPHA=1），最高 10 MHz
- **当前主程序未调用 BMI088 初始化**，IMU 数据未接入控制流，为预留功能

## 二、需要小改的功能模块

### `FunctionalModule/GraySensor.c` — ADC 调用内嵌

`GraySensorDataUpdate()` 内部直接调用了 DriverLib API：

```c
// 需要替换的 3 处 DriverLib 调用（在 READ_GRAY_ADC 宏中）：
DL_ADC12_enableConversions(ADCGraySensor_INST);
DL_ADC12_startConversion(ADCGraySensor_INST);
while (DL_ADC12_getStatus(...) != DL_ADC12_STATUS_CONVERSION_IDLE);
DL_ADC12_stopConversion(ADCGraySensor_INST);
DL_ADC12_disableConversions(ADCGraySensor_INST);
gAdcResult = DL_ADC12_getMemResult(ADCGraySensor_INST, ADCGraySensor_ADCMEM_C5);
```

**建议做法**：在 HardwareDriver 层新增一个 ADC 抽象函数：

```c
// 在 HardwareDriver/Adc.h 中声明
// 触发一次 ADC 转换并返回 12 位原始值（0~4095）
uint16_t ADC_ReadGraySensor(void);
```

然后将 `READ_GRAY_ADC` 宏替换为调用该函数，`GraySensor.c` 其余代码无需修改。

## 四、迁移步骤建议

### Phase 1：建立系统基础（先跑起来）

1. 移植 `System.c`：实现 `millis()` / `delay_ms()` / `delay_us()`
2. 移植 `Timer.c`：配置 3 个定时器，能定时调用 `duty_200hz` / `duty_100hz` / `duty_10hz`
3. 移植 `Uart.c`：实现 `uart0_send_char` 和 `uart_printf`，验证串口输出正常

### Phase 2：传感器

4. 移植 ADC 抽象 + `GraySensor.c`：接好 MUX 后串口打印 8 路原始 ADC 值验证
5. 移植 `EncoderExti.c`：手动转动轮子，串口打印 `EncoderCount` 验证方向和计数

### Phase 3：执行器

6. 移植 `Pwm.c`：先用示波器验证 4 路 PWM 波形频率和占空比正确
7. 验证方向 GPIO + PWM 联合：给固定输出，确认 4 个电机转向符合预期

### Phase 4：闭合控制环

8. 上电，短按按键加圈数，长按启动，验证循迹和过弯逻辑

### Phase 5：可选（当前未启用）

9. 移植 `IIC.c` + OLED：显示调试信息
10. 移植 `BMI088Middleware.c`：如需 IMU 辅助姿态

## 五、Key.c 的 GPIO 读取方式

`Key.c` 中读键值用了直接寄存器访问：

```c
#define read_key   ((Key_PORT->DIN31_0 & Key_KeyPutIN_PIN) ? 0x01 : 0x00)
```

移植时将 `Key_PORT->DIN31_0` 和 `Key_KeyPutIN_PIN` 替换为目标平台的 GPIO 读函数即可，其余按键逻辑（短按/长按判断、200 Hz 采样计数）不需要修改。
